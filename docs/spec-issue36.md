## ヒアリング結果（2026-07-24 確定）

1. **ライセンス付与単位**: ユーザー（アカウント）単位。1 回購入で lifetime 相当。帳には持たない
2. **制限の判定**: 常にその帳の `ownerUid` のライセンスで決める。メンバーはオーナーの権利を借りる
3. **無料枠**: 商品 20 / 店舗 3（オーナー帳ごと）。価格記録・カテゴリ・底値比較は制限なし
4. **CSV**: 無料は不可。購入済みオーナーの共有帳では、無料メンバーもその帳に限り可
5. **招待**: 無料ユーザーは参加可・発行不可。未購入オーナーは発行操作のみ不可＋購入 CTA（セクションは表示維持）
6. **既存超過**: 既存データは維持。新規追加のみブロック。削除で枠が空き追加再開可
7. **既存共有**: 未購入オーナー帳の既存参加関係は維持。新規招待発行のみ止める
8. **導線**: 本仕様に置き場所と振る舞いまで書く。金額・Stripe・特商法は #37
9. **永続化**: `users/{uid}` に `license` オブジェクト（現状 `users` コレクションは未使用のため新規）

## 前提（仮定 — 誤りがあれば指摘してください）

1. **本 Issue は仕様承認のみ**。UI / Firestore / Rules / Functions の実装は後続（主に #37 および必要なら別 Issue）
2. **`users/{uid}` が無い、または `license` が無い**場合は `status: 'free'` とみなす（既存ユーザーの移行バッチは不要）
3. **商品・店舗の件数**は、当該 book 配下の現行ドキュメント数（ハードデリート後は枠が空く）。ソフトデリートは現行どおり無い
4. **現状は `bookId === uid` でオーナー帳は 1 つ**。枠は「オーナー帳ごと」と定義し、将来の複数オーナー帳にも同じ規則を適用する
5. **共有帳の商品・店舗は、メンバー個人の無料枠にカウントしない**（自分のオーナー帳に戻ると個人枠が再適用される）
6. **未購入オーナーの共有帳**でも、帳の上限はオーナーの無料枠（商品 20 / 店舗 3）。メンバー追加も同じ枠を消費する
7. **価格・決済手段・領収・特商法・Webhook** は本仕様の対象外（#37）
8. **管理者プロモで lifetime を付与する経路**は #38。本仕様のデータ形（`license.status`）はそれに耐える
9. **クライアント表示とサーバー強制の詳細**（Rules で create を弾くか、Functions のみか）は実装 Issue で確定する。本仕様は「正しい振る舞いに見える／書き込めてはならない操作」を定義する
10. **利用規約・表記の無料前提**は #37 側で更新する前提とし、本仕様ではライセンスモデルのみ固定する

## Objective

### 何を作るか（本 Issue）

Web アプリ「そこねこ」に、App Store 買い切りに近い **一回払い・lifetime** のライセンスモデルを仕様として固定する。無料の一定範囲利用を許可し、世帯での常用時に買い切りへ誘導する。無料枠・共有ゲスト・既存データの扱いを矛盾なく定義し、後続の決済実装（#37）の前提にする。

### 背景・課題

現状は個人運営の無料サービス。収益化方針としてサブスクではなく買い切りを採用したい。無料枠・購入者帳への無料ユーザー参加・招待発行の可否はライセンスモデルに強く依存するため、決済実装の前に仕様を単一の真実として固定する必要がある。

### ユーザーストーリー

- お試し利用者として、商品・店舗を一定数まで無料で登録し、底値記録・比較を試したい
- 世帯で常用するオーナーとして、買い切り後は無制限に使え、家族を招待したい
- 招待された無料ユーザーとして、購入済みオーナーの共有帳では制限なく記録・閲覧・CSV したい
- 無料のまま自分の帳を使うときは、無料枠が再適用されていてほしい
- すでにデータを多く持っているユーザーとして、導入時に既存データを消されたくない

### 3 パターンの一文説明（受け入れ条件）

| パターン | 振る舞い |
|---|---|
| **無料オーナー（自分の帳）** | 商品 20 / 店舗 3 まで。招待発行不可。CSV 不可。超過後は既存維持・新規追加のみ不可 |
| **買い切りオーナー** | 自分の全オーナー帳が無制限。招待発行可。CSV 可 |
| **共有ゲスト** | 参加中の帳については **オーナーのライセンスを借りる**。購入済みオーナーの帳なら無制限＋CSV 可（その帳に限る）。未購入オーナーの帳なら無料枠が帳に適用。ゲスト自身のオーナー帳に戻ると自分の無料枠が再適用 |

## データモデル案

### 新規: `users/{uid}`

```
users/{uid}
  license: {
    status: 'free' | 'lifetime'   // 必須相当。欠落時は free 扱い
    purchasedAt?: Timestamp       // lifetime 付与時刻（#37 / #38 で設定）
    source?: 'stripe' | 'promo' | string  // 将来用。本 Issue では値の列挙を強制しない
  }
  // 他フィールドは本 Issue で必須にしない（プロフィール等は将来可）
```

- **文書 ID** は Firebase Auth の `uid`
- **読み取り**: 本人は自分の doc を読めること（実装時 Rules）。他人の `license` をクライアントが広く読めない設計を基本とする
- **帳の制限判定でオーナーの license が必要**な場合: メンバーがオーナーの license を直接読めないなら、Cloud Function / 集約フィールド等で解決する（方式は実装 Issue で Ask first）。仕様上の真理は「オーナーの `users/{ownerUid}.license`」にある
- **書き込み**: クライアントが勝手に `lifetime` にできないこと（#37 の Webhook / Admin / #38 のプロモのみが昇格）

### 既存モデルとの責務分離

| 関心事 | 置き場所 | 備考 |
|---|---|---|
| 誰が帳のオーナーか | `books/{bookId}.ownerUid` | 変更不可（既存） |
| 誰が参加しているか | `books/{bookId}.memberUids` + `members` | 共有の真実（#7） |
| 招待トークン | `invites/{code}` + `joinTokens` | 発行可否はライセンスでゲート |
| 利用権（無料/買い切り） | `users/{uid}.license` | **本 Issue で追加**。book には持たない |

`invites` の作成権限は「book オーナー」に加え、仕様上「そのオーナーが `lifetime`」であることが必要。既存の有効な `invites` ドキュメントの扱いは「期限まで参加に使える／新規作成のみ止める」でよい（実装で無効化バッチは必須にしない）。

## 無料枠・機能マトリクス

対象: **その帳のオーナーの license**（閲覧中ユーザー自身の license ではない）

| 項目 | オーナー free | オーナー lifetime |
|---|---|---|
| 商品 | 最大 20（帳ごと） | 無制限 |
| 店舗 | 最大 3（帳ごと） | 無制限 |
| 価格記録 | 商品上限内なら自由 | 自由 |
| カテゴリ | 制限なし | 同じ |
| 底値・比較 | 利用可 | 同じ |
| 招待の発行 | 不可 | 可 |
| 招待への参加 | （参加者側の権利）無料でも可 | 可 |
| CSV エクスポート | 不可 | 可（現在開いている帳） |

補足:

- ゲストが自分のオーナー帳にいるときは、自分の license で上表を適用
- ゲストが購入済みオーナーの共有帳にいるときは、その帳について lifetime 列を適用。件数はゲスト個人枠に加算しない
- すでに 20 / 3 を超えている帳: **閲覧・既存の編集・価格記録の追加/編集は可**。商品・店舗の **新規作成のみ不可**

## UX 仕様（導線の置き場所と振る舞い）

金額・決済フォームは出さない（#37）。コピーは「買い切りで無制限」程度の誘導でよい。

### 1. 設定

- **ライセンス状態**: 「無料プラン」または「買い切り（lifetime）」を表示
- **無料時**: 自分のオーナー帳について、商品・店舗の使用数 / 上限（例: 商品 12/20）を表示
- **無料時**: 買い切りへの CTA（詳細・決済は #37 で接続）
- **CSV**（#20 の設定内ボタン）: 現在の帳のオーナーが free なら実行不可（無効化またはタップで CTA）。lifetime なら現行どおりダウンロード

### 2. 商品・店舗の追加 UI

- 上限未満: 残り件数を近くに提示（例: 「残り 3 件まで追加できます」）
- 上限到達・超過: 追加ボタンを無効化（または送信時に拒否）し、購入 CTA を表示
- 既存商品・店舗の編集・削除、価格記録はブロックしない

### 3. 共有（`ShareSettings`）

- セクション自体は表示維持
- 未購入オーナー: 「招待リンクを発行」を不可にし、購入 CTA（「買い切り後に招待できます」）
- メンバー一覧・メンバー削除・退出・招待コードでの参加導線は、既存仕様（#7）どおり維持
- 購入済みオーナー: 現行どおり発行可

### 4. 突然ロックしない

- 導入瞬間に既存データを読めなくしない
- 上限超過帳でも記録・比較・閲覧は継続可能

## Code Style（実装時）

親仕様 `docs/spec.md` に従う。判定は UI に散在させず、純粋関数に寄せる例:

```ts
export type LicenseStatus = 'free' | 'lifetime';

export function resolveLicenseStatus(
  license: { status?: LicenseStatus } | null | undefined,
): LicenseStatus {
  return license?.status === 'lifetime' ? 'lifetime' : 'free';
}

/** 帳に対する権限は常にオーナーの license で決める */
export function canAddProduct(ownerLicense: LicenseStatus, productCount: number): boolean {
  if (ownerLicense === 'lifetime') return true;
  return productCount < 20;
}
```

## Boundaries

- **Always**
  - 制限判定は帳オーナーの license を用いる
  - 無料枠はオーナー帳ごと商品 20 / 店舗 3
  - 既存データ維持・新規追加のみブロック
  - 共有のメンバーシップ真実は `memberUids` / `invites` のまま（license に混ぜない）
  - 本 Issue では仕様書のみを成果物とする
- **Ask first**
  - 無料枠数値の変更
  - ライセンスを book 単位課金に変えること
  - メンバーがオーナー license を読むための具体アーキテクチャ（Rules 直読 / 集約 / Functions）
  - 既存未購入共有の一括解散や招待の強制無効化
  - サブスク・広告モデルへの変更
- **Never**
  - 本 Issue で Stripe / 特商法 / プロモ実装に手を出さない
  - クライアントだけで `lifetime` を永続化できる設計にしない（昇格はサーバー側）
  - 導入時に既存共有メンバーを自動削除しない
  - 無料ユーザーの「招待への参加」まで禁止しない
