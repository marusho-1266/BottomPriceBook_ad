3. **商品管理画面でも新規登録できる**: 一覧からの追加を含める。
   記録画面の「+ 新しい商品を登録」は**維持**する
4. **メモ(`note`)を今回スコープに含める**: 登録・編集フォームで入力・保存・表示する。
   Firestore ルールは既に `note`(任意・最大 500 文字)を許可済み。スキーマ追加は不要
5. **UI パターンは既存準拠**: カテゴリ／店舗管理と同様の一覧 + 追加フォーム +
   行の編集／削除。編集 UI は既存 `ProductForm`(拡張)を再利用する
6. **カテゴリ変更制限(M-1)は現行どおり**: 同一 `baseUnit` のカテゴリへの変更のみ許可。

7. **削除は既存 H-2**: 確認ダイアログ後、`deleteProductWithRecords` で配下の
   価格記録もまとめて削除する(分割バッチ・L-5)
8. **Firestore スキーマ変更なし / 新規 npm 依存なし**
9. **共有 book**: カテゴリ／店舗と同様、メンバーも登録・編集・削除できる
   (オーナー限定にしない)
10. **役割分担の整理**:
    - 設定・商品管理 = 商品マスタ(名前・カテゴリ・メモ)の CRUD
    - 商品詳細 = 底値・履歴の閲覧 + 価格記録の編集／削除(H-1)
    - 記録 = 店頭での価格入力 + その場の商品／店舗追加
11. **親仕様・関連仕様の更新**: `docs/spec.md` の画面構成「設定」に商品管理を追記し、
    `docs/spec-issue32.md` の「編集・削除は商品詳細の責務」は
    **価格記録の編集・削除**に限定する旨へ整合させる

## Objective

### 何を作るか

設定配下に商品管理画面を追加し、商品マスタ(名前・カテゴリ・メモ)の
一覧・登録・編集・削除を可能にする。商品詳細からは編集画面への導線を置く。

### 誰のためか

- 商品名の誤記やカテゴリの付け間違いを直したい買い物客
- 使わなくなった商品を履歴ごと整理したい買い物客
- 設定でカテゴリ・店舗と同様にマスタを整えたい利用者

### ユーザーストーリー

- 買い物客として、設定から商品一覧を開き、名前・カテゴリ・メモを編集したい
- 買い物客として、設定の商品管理から新しい商品を登録したい
- 買い物客として、不要な商品を確認のうえ削除し、配下の価格記録も消したい
- 買い物客として、商品詳細を見ていて名前等が気になったら、そこから商品情報の編集へ進みたい
- 買い物客として、店頭の記録画面からは従来どおりその場で商品を追加したい

## Tech Stack

`docs/spec.md` を継承。新規依存パッケージの追加は不要。
既存の `ProductForm` / `addProduct` / `updateProduct` / `deleteProductWithRecords` /

## 機能仕様

### ルートとナビ

| 要素 | 内容 |
|---|---|
| パス | `/settings/products` |
| 設定リンク | カテゴリ管理・店舗管理と同じカード内に「商品管理」を追加 |
| 戻る | `SubPageHeader` で設定(`/settings`)へ戻る |
| 商品詳細導線 | 「商品情報を編集」→ `/settings/products`。  
  該当商品をすぐ編集できるよう、クエリ(例: `?edit=:productId`)または
  同等の手段で対象を示してよい。実装詳細は Plan で確定 |

### 一覧

- `useProducts()` の結果を表示(既存どおり名前順)
- 各行に少なくとも **商品名** と **カテゴリ名**(解決できない場合は「(未分類)」等の
  既存フォールバック方針に合わせる)を表示
- メモがある場合は一覧または編集モードで確認できること(一覧に全文必須ではない。
  編集フォームで必ず見えること)
- 空状態: 商品が 0 件のとき案内文を表示し、追加フォームへ誘導する

### 新規登録

- 画面上部(または一覧上部)に追加用の `ProductForm`(submitLabel 例: 「登録」)
- 入力: 商品名(必須)・カテゴリ(必須)・メモ(任意)
- 成功後: フォームをクリアし、一覧に反映(リアルタイム購読のため追加の再取得は不要)
- 記録画面のその場登録フローは変更しない(ただし共通フォームに `note` を足した場合、
  記録画面の新規登録でもメモ入力が可能になるのは許容。記録フローを壊さないこと)

### 編集

- 行の「編集」で編集モードに入る。`ProductForm` に `initial`(name / categoryId / note)を渡す
- 保存時は `updateProduct` で `{ name?, categoryId?, note? }` を更新
- カテゴリ変更は同一 `baseUnit` のみ(既存 `ProductForm` の disabled + 案内文)
- メモを空にした保存は「メモなし」として扱ってよい
  (`note` を空文字で書く / フィールド削除のいずれでも可。ルールの任意文字列制約を満たすこと)

### 削除

- 行の「削除」で確認ダイアログを出す
- 確認メッセージに含めること(一字一句固定は不要):
  - 商品名
  - 配下の価格記録も削除されること
- 同意後に `deleteProductWithRecords(db, bookId, productId)` を呼ぶ
- キャンセル時は何もしない

### 商品詳細からの導線

- 商品詳細ページのヘッダー付近または履歴セクションより上に、
  「商品情報を編集」リンク(または同等のボタン)を置く
- 遷移先は商品管理。価格記録の鉛筆アイコン(記録編集)と混同しない文言・配置にする
- PC 右ペイン(`PcProductDetailPane`)には編集 UI を置かない方針は維持。
  「詳細を開く」→ 商品詳細 →「商品情報を編集」の二段でもよい
  (右ペインに直接「商品情報を編集」を足すのは任意・本 Issue の必須ではない)

## API / フォーム差分

### `ProductForm`

- 値に `note?: string` を追加(入力は任意、トリム後に空なら未設定扱い)
- ラベル例: 「メモ」(プレースホルダは任意、例: 「容量違いの注意など」)
- 既存の名前・カテゴリバリデーションと M-1 制限は維持

### `addProduct` / `updateProduct`

- `note` を受け渡せるようにする
- `note` 未指定時の挙動:
  - 新規: フィールド省略または空文字のいずれでも可(ルール適合)
  - 更新: パッチに含めない場合は既存値を維持。空にしたい場合は明示的に空文字等を送る

レートリミット用 `writeBatch` 化は現行どおり維持する。

## 親仕様への差分

実装時に次の趣旨で更新する:

- 画面構成「設定」に **商品管理**(登録・編集・削除・メモ)を追記
- 商品詳細の説明は、価格記録の編集・削除(H-1)に加え、
  商品マスタ編集への導線がある旨を短く追記してよい
- Success Criteria の「商品・店舗・カテゴリを登録でき…」周辺と整合する文言があれば更新

### `docs/spec-issue32.md`

- 「編集・削除は従来どおり商品詳細ページから」は
  **価格記録の編集・削除**に限定する旨へ更新
- 商品マスタの編集・削除は設定の商品管理が正式な場所である旨を追記
  (実装済みドキュメントの履歴注記として、本 Issue による更新である旨を残す)

## Code Style

```tsx
/** 設定配下の商品マスタ管理。登録・編集・削除(配下記録含む) */
export function ProductsPage() {
  // useBook / useProducts / useCategories
  // ProductForm(追加) + 一覧行(編集モードで ProductForm、削除は confirm)
}
```

- コンポーネントは named export。カテゴリ／店舗ページと同じ構成感を保つ
- Firestore アクセスは `features/products/api.ts` および既存 `deleteProduct.ts` に集約
- UI 文言は日本語

## Testing Strategy

`docs/spec.md` の Testing Strategy を継承。本機能では以下を追加する:

| レベル | 対象 |
|---|---|
| コンポーネント | `ProductForm`: メモ入力を含めて submit されること。編集時 M-1 制限が維持されること |
| コンポーネント | `ProductsPage`: 登録・編集・削除(confirm 同意時に API 呼び出し)ができること |
| コンポーネント | `ProductDetailPage`: 「商品情報を編集」が商品管理へ進むこと |
| コンポーネント | `SettingsPage`(またはリンクの存在確認): 「商品管理」リンクがあること |
| 手動 | 設定から登録→編集→削除、商品詳細からの導線、記録画面のその場登録が壊れていないこと |

既存の `deleteProductWithRecords` / ルールテストは流用。新規のルール変更はない。

## Boundaries

- **Always**
  - コミット前に `npm run lint` と `npm run test` を通す
  - カテゴリ変更の M-1 制限を壊さない
  - 削除前に確認ダイアログを出す
  - 記録画面のその場登録フローを壊さない
  - 価格記録の編集 UI と商品マスタ編集の導線を混同させない
- **Ask first**
  - Firestore スキーマやセキュリティルールの変更
  - 新規 npm 依存の追加
  - PC 右ペインへの商品編集導線の追加(本 Issue の必須外)
  - 商品管理の検索・カテゴリ絞り込み等の追加 UX(本 Issue の必須外)
- **Never**
  - 商品削除で配下記録を残したまま商品だけ消す実装に戻すこと
  - 異なる `baseUnit` へのカテゴリ変更を許可すること
  - シークレットのコミット、失敗テストの無断スキップ

## Success Criteria

- [ ] 商品詳細から「商品情報を編集」で商品管理へ進める
- [ ] 記録画面からの新規商品登録が従来どおり動く

## Out of Scope

- 商品管理の高度な検索・ソート・一括操作
- 買い物リスト・バーコード・商品写真
